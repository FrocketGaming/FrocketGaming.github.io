## Python 3.15 Changes

### Lazy Imports!
This is a cleaner solution to explicitedly load in packages only when they're needed instead of at run time. It makes your code more readable because you no longer need to move the import to the function that requires in. For me, this is specifically great for CLI tools.

#### Examples:
```python
lazy import json
lazy from pathlib import Path

print("Starting up...")  # json and pathlib not loaded yet

data = json.loads('{"key": "value"}')  # json loads here
p = Path(".")  # pathlib loads here
```

```python
__lazy_modules__ = ["json", "pathlib"]

import json     # lazy
import os       # still eager
```

- [Read more about Lazy Imports](https://docs.python.org/3.15/whatsnew/3.15.html#whatsnew315-lazy-imports)

### Unpacking Comprehensions
This is something I haven't needed a lot but it's been an annoying and difficult thing to read if I did need it.

Currently, flattening a list of lists takes two `for` clauses, and the name you want in the result (`item`) comes first, before the loops that define it:

**Approach 1**
```python
lists = [[1, 2], [3, 4], [5]]

flat = [item for row in lists for item in row]
# [1, 2, 3, 4, 5]
```

You read it left to right, but it runs right to left: `row` comes from `nested`, then `item` from `row`. If you want to avoid that, `itertools` already has a plain version:

**Approach 2**
```python
from itertools import chain
lists = [[1, 2], [3, 4], [5]]
flat = list(chain.from_iterable(lists))
```

but if you want to avoid itertools you can now do it like this in 3.15.

**New Approach**
```python
lists = [[1, 2], [3, 4], [5]]
flat = [*row for row in lists]
# [1, 2, 3, 4, 5]

# Also works for sets!
sets = [{1, 2}, {2, 3}, {3, 4}]
flat = {*s for s in sets}
# {1, 2, 3, 4}

# and dictionaries
dicts = [{'a': 1}, {'b': 2}, {'a': 3}]
flat = {**d for d in dicts}
# {'a': 3, 'b': 2}
```

- [Read more about unpacking comprehensions](https://docs.python.org/3.15/whatsnew/3.15.html#whatsnew315-unpacking-in-comprehensions)

## Package Reviews

Three packages that work well together: Polars for transforming data, DuckDB for querying it with SQL, and PyTrendy for finding the trends in it.

### Polars
A fast, expressive DataFrame library built on Arrow. The part worth learning first is the lazy API: `scan_csv()` builds a query plan instead of loading the file, and Polars pushes your filters and column selections down so it only reads what the result needs. Everything is written as expressions, so there is no row-by-row `apply`.

#### Example:
```python
import polars as pl

top_regions = (
    pl.scan_csv("sales.csv")
    .filter(pl.col("amount") > 0)
    .group_by("region")
    .agg(pl.col("amount").sum().alias("total"))
    .sort("total", descending=True)
    .collect()
)
```

- [Read more about Polars](https://pola.rs/)

### DuckDB
An in-process analytical SQL database. There is no server to set up: you point it at CSV, Parquet, or JSON files and query them directly. It also reads Polars DataFrames sitting in your Python session by variable name and hands results back as Polars, so it is easy to use alongside the previous package. I reach for it when the logic is easier to say in SQL than in expressions, like a multi-step join.

#### Example:
```python
import duckdb
import polars as pl

# query a file directly, no loading step
totals = duckdb.sql("""
    select region, sum(amount) as total
    from 'sales.csv'
    group by region
    order by total desc
""").pl()

# query a DataFrame that is already in memory
df = pl.DataFrame({"region": ["east", "west", "east"], "amount": [10, 20, 30]})
duckdb.sql("select region, count(*) as orders from df group by region").pl()
```

- [Read more about DuckDB](https://duckdb.org/)

### PyTrendy
A trend-detection package for time series. It labels each stretch of your data as an up, down, or flat segment, and it is built to handle noisy and flat data, catching both gradual and abrupt trends with fewer false positives than naive approaches. Each detected segment comes back with its start and end dates, duration, and change size, so you can rank them.

It is built on pandas, so if the rest of your pipeline is Polars, convert at the boundary with `to_pandas()`.

#### Example:
```python
import pytrendy as pt

df = pt.load_data("series_synthetic")
results = pt.detect_trends(df, date_col="date", value_col="gradual", plot=True)
results.print_summary()

# the full table: direction, start, end, days, total_change, change_rank, ...
segments = results.df

# only the upward trends, ranked by size
results.filter_segments(direction="Up", sort_by="change_rank")
```

Install with `uv add pytrendy`. Using your own data:

```python
# polars_df needs a date column and a numeric value column
results = pt.detect_trends(polars_df.to_pandas(), date_col="date", value_col="value")
```

- [Read more about PyTrendy](https://github.com/RussellSB/pytrendy)

## New to Python?

A few small habits that pay off once you're past the basics.

### Debug with self-documenting f-strings
Instead of `print("x:", x)`, add a trailing `=` inside the f-string and Python prints both the expression and its value for you.

```python
x = 42
print(f"{x=}")
# x=42

name = "ada"
print(f"{name.upper()=}")
# name.upper()='ADA'
```

- [Read more about self-documenting expressions](https://docs.python.org/3/tutorial/inputoutput.html)

### Skip the manual counter with `enumerate()`
If you catch yourself writing `range(len(items))` just to get an index, `enumerate()` does it in one step and reads better.

```python
items = ["a", "b", "c"]

# instead of this
for i in range(len(items)):
    print(i, items[i])

# do this
for i, item in enumerate(items):
    print(i, item)
```

- [Read more about enumerate()](https://docs.python.org/3/library/functions.html#enumerate)

### Unpack just the parts you need with `*`
You don't have to unpack every value one at a time — a single `*` grabs "everything else" into a list.

```python
first, *rest = [1, 2, 3, 4]
# first = 1, rest = [2, 3, 4]

*init, last = [1, 2, 3, 4]
# init = [1, 2, 3], last = 4
```

- [Read more about extended unpacking](https://docs.python.org/3/reference/simple_stmts.html#assignment-statements)
